# 产品经理工作台：开发与验收边界

本仓库是 AionUi（Electron / React）与 AionCore（Rust）的二次开发版本，对外名称为「产品经理工作台」。两个目录保持同级。

## 运行形态

- Electron 使用 `pages/Workbench/` 三栏外壳：AI 对话与账号管理、飞书、独立账号浏览器。
- WebUI 使用原有 `components/layout/Layout.tsx` 与 Sider，保留会话和设置导航；账号 webview 与本地飞书授权只属于桌面端。旧布局不是待删除的死代码。
- `mobile/` 是独立工程，本次没有更改。
- 工作台圆润线性图标使用用户指定方向引入的 `lucide-react`；其他界面继续使用 Icon Park。

## 同步与本地授权

设置页「飞书授权」复用本机 `lark-cli`。登录由官方 CLI 完成，凭证不传入渲染进程。CLI 未安装或未配置时显示对应状态。浏览器登录与 CLI 授权是两套状态。

新同步默认只写入三个文本字段：**用户、时间、评论**。来源账号、评论 ID 和去重键保存在本地日志。CLI 通道先检查目标字段及已有行，记录待核对批次，再批量写入并回读。失败不自动重发，不确定批次必须核对后才能继续。旧七列运行保留原有布局。

## REPL 信任边界

浏览器 REPL 在 Node worker 中执行授权的 Agent 代码，**没有操作系统级沙箱**。Worker 隔离用于超时终止和生命周期管理，不是文件系统、网络或进程权限隔离。工具说明中的禁止事项、页面脚本过滤及 CDP 路由检查均不能把恶意 Node 代码变成安全代码。

因此当前版本仅适合可信本机用户及其授权的 Agent 工作流；不能以此实现不可信代码托管或多租户隔离。对外分发时必须保留这一说明，不得宣称安全沙箱。站点页面和评论内容属于不可信输入，不能作为扩大授权的依据。

## 构建依赖与源码提交

源码构建必须先执行 `bun install --frozen-lockfile`，包括开发依赖；随后可运行 `bun run package`。`electron-vite`、`esbuild`、TypeScript 等都是构建工具，保留在 devDependencies。当前 CI 同样安装完整依赖。`--production` 仅适用于不再编译源码的运行阶段，不能用来准备构建环境。

Vite 主进程构建结束后生成独立 MCP 与 REPL worker bundle；打包脚本也会生成它们，以覆盖跳过 Vite、复用缓存产物的路径。最终应用使用已生成并解包的 bundle，不在用户启动时运行 esbuild。

源代码包是导出时点的快照，可能包含未提交文件；不能替代 Git 提交。提交功能时检查新增文件和测试是否已纳入，区分无关的 Rust 改动。不要使用清理或重置命令代替提交。
