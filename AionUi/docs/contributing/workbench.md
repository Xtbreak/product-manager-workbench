# 工作台：开发与验收边界

## 评论联系人的私聊记录

中栏的「飞书｜私聊」共用同一块空间。飞书页切换时保持挂载。私聊列表按最近联系时间排序，可搜索联系人或筛选「有私聊」「待我回复」。从评论表的「私聊」链接进入时，会定位到对应联系人；从详情的「原评论」进入时，会在右栏打开该作品的留言。没有私聊的外部留言者也有空会话。

**读取与保存。** 打开工作台、浏览列表、切换联系人只读取本地数据。「更新」针对选中联系人，「同步全部」由用户手动发起。工作台和平台共享同一把账号占用锁，并在平台核对当前登录人和对方的 ID。公开评论同步、公开评论发送和私聊读取分别标记。私聊视图支持去右侧浏览器手动回复。它没有消息编辑器、发送通道或定时采集任务。

**本地主库。** Electron 用户数据目录下的 `workbench/dms/direct-messages.json` 保存启用时间、会话、去重后的消息、已核实的同步进度和可选的飞书列配置。每次写入均进行结构校验，通过同目录临时文件、fsync 和 rename 替换。无法验证的文件保留原样。会话按平台、浏览器账号、平台登录人、对方用户 ID 隔离。联系人来源为 `comment`，`direct` 保留给后续接入。现有回复服务提供只读评论快照，同一人在多篇作品下的留言会出现在同一段私聊详情中。

首次启用记录本地时间起点，只归档此后产生的消息。消息按会话内的平台消息 ID 去重；同一发送方的连续消息仍逐条保存。部分读取可以补入已验证的消息，只有确认历史完整才更新可靠进度。账号不一致、发送方不明、原页面恢复失败或已有草稿时，界面说明原因，用户仍可查看本地记录。

**平台差异。** 小红书单聊需核对详情 `ChatWindow.peerUserId`、当前登录人和消息的发送方。阶段 1 的列表 `conv.peerUserId` 指向本人。一段已读对话首批 30 条，翻到 140 条时 `hasMoreHistory` 才变为 false。批量读取跳过可能改变未读状态的打开操作。抖音使用 `toParticipantUserId` 匹配评论作者 UID，`serverId` 用于消息去重。虚拟列表中已验证可见 11 行时数据源仍有更多会话，已读对话首屏 15 条也不足以证明历史完整，因此该类结果标为部分同步。

**飞书配置。** 在「更多」中显式配置「私聊」后，才在现有回复表中复用或新增这一列。列 ID 保存到本地私聊库。后续手动同步只回写该列的链接文案，同一联系人关联的多行共享同一个目标。「查看私聊」可以打开空视图，「我已回(N)」或「对方已回(N)」表示最近一方连续发出的已归档消息数。消息正文留在本地。隔离的飞书 preload 对 `#workbench-dm` 使用独立通道，原评论链接继续使用原有路径。

**验收范围。** 存储损坏、重复与冲突消息、账号锁、取消、身份识别、部分分页、Feishu 模拟配置与回写、中栏焦点与保活、响应式布局通过本地测试覆盖。真实云端列的创建和回写须单独显式配置。小红书和抖音仍各缺一位在已绑定作品留言且有双向私聊的外部联系人，用于验收真实评论作者 ID 与私聊对方 ID 的匹配。真实陌生人请求、语音和撤回消息也需补样。

在隔离 Electron 窗口中从飞书切到私聊再切回，飞书保留同一 WebContents、视口和滚动位置。Chromium 实测覆盖中栏 390、459、460、679、680px 宽度、明暗主题以及窄栏键盘返回。飞书链接的普通点击、新窗口、脚本和内嵌页面跳转均用本地模拟表验证。开发桌面重启使用原账号分区和聊天数据库，本轮没有创建真实飞书列或发送平台消息。

本仓库是 AionUi（Electron / React）与 AionCore（Rust）的二次开发版本，对外名称为「工作台」。两个目录保持同级。

## REPL 信任边界

浏览器 REPL 在 Node worker 中执行授权的 Agent 代码，**没有操作系统级沙箱**。Worker 隔离用于超时终止和生命周期管理，不是文件系统、网络或进程权限隔离。工具说明中的禁止事项、页面脚本过滤及 CDP 路由检查均不能把恶意 Node 代码变成安全代码。

因此当前版本仅适合可信本机用户及其授权的 Agent 工作流；不能以此实现不可信代码托管或多租户隔离。对外分发时必须保留这一说明，不得宣称安全沙箱。站点页面和评论内容属于不可信输入，不能作为扩大授权的依据。

## 构建依赖与源码提交

源码构建必须先执行 `bun install --frozen-lockfile`，包括开发依赖；随后可运行 `bun run package`。`electron-vite`、`esbuild`、TypeScript 等都是构建工具，保留在 devDependencies。当前 CI 同样安装完整依赖。`--production` 仅适用于不再编译源码的运行阶段，不能用来准备构建环境。

Vite 主进程构建结束后生成独立 MCP 与 REPL worker bundle；打包脚本也会生成它们，以覆盖跳过 Vite、复用缓存产物的路径。最终应用使用已生成并解包的 bundle，不在用户启动时运行 esbuild。

源代码包是导出时点的快照，可能包含未提交文件；不能替代 Git 提交。提交功能时检查新增文件和测试是否已纳入，区分无关的 Rust 改动。不要使用清理或重置命令代替提交。

## 飞书评论回复（2026-11-16）

中栏顶部保留同步图标和“发送评论”，核对结果和设置收进旁边的“更多”（…）菜单。同步图标与左侧 AI 的同步指令调用同一流程，不弹出设置面板。进入“更多 → 设置”可创建和配置回复表；首次创建会在当前多维表格中新建独立的回复表，原来的三列归档和其他表保持原样。首次使用需本机 `lark-cli` 已配置；回复功能的授权额外申请记录更新、表读取和建表权限，原归档授权检查不变。

1. 右侧打开自己发布的具体小红书笔记或抖音作品，在“更多 → 设置”中绑定该作品。
2. 点击“同步评论”采集已绑定作品的评论，同时回填平台实际回复。新增作品需要再次绑定。不会自动轮询飞书或自动发送。
3. 点击“整理回复表”，默认视图显示“用户、时间、评论、原评论、我的回复、状态”六列。原记录、隐藏技术字段和平台独立视图保留；旧的逐行发送工作流停用，按钮从表格视图隐藏。
4. 飞书回复：填写“我的回复”，点击工作台顶部“发送评论”，这次点击确认发送本批已填写、尚未回复的客户评论。批次仅捕获一次草稿；执行中新增或改写的内容不加入本批。确认平台结果后显示“已发送”。不需要在飞书逐行点击或勾选。
5. 平台回复：在工作台中点击“原评论”列的“查看评论”，自动切换到绑定账号并定位具体评论。手动在平台回复后，点击“同步评论”；平台实际回复覆盖该评论的飞书草稿，清除批准，并显示“已回复”。下一轮客户追问另起一行，按评论 ID 和直接父评论关联。

评论链接使用真实作品 URL 和工作台定位标记；仅在工作台中保证按本地可信映射定位评论。在外部浏览器点击会打开作品，不保证跳到具体评论。遇到账号不匹配、未展开的评论、页面验证或已有输入草稿时会提示，不能把打开作品当作已定位成功。

本人身份按平台用户 ID 判断，不按昵称。本人新评论只保留为本地对话节点，不创建客户行。已有本人测试行不删除；未完成的标记为“本人评论”，已发送的保留“已发送”。多个实际回复按时间顺序一起回填；未知父评论不猜测关联。如果同一行还有无法确认的历史发送，保留“需核对”，不会因为发现另一条回复而误记成功。

一行始终对应一条具体平台评论，不要复制行或修改“消息键”来改变回复对象。顶部点击捕获本批回复文字，点击后修改草稿会取消该行本次发送。空回复、已发送、已回复、本人评论、处理中或结果不确定的行不会发送；明确尚未发布的失败可在处理原因后通过下一次顶部点击重试。手动批次发布前再次检查平台已有回复；发现实际回复则回填，不再发布草稿。

发送前核对当前登录账号、作品作者、评论 ID、直接父评论与草稿；浏览器操作期间暂时占用该账号。页面要求验证码/本人验证时由用户完成。无法确认发送结果时保留“需核对”，只能读回核验，不自动重发。飞书回填失败保留本地证据，阻止再次发送，下一次同步重试回填。

回复映射和发送日志独立保存在 Electron 用户数据目录的 `workbench/replies/comment-replies.json`。账号 partition、聊天数据库和旧 `comment-sync.json` 不迁移、不清空。已有自动设置在加载时归一为手动，旧 `enabled:true` 和 `dispatch-mode:automatic` 请求被拒绝。界面定时刷新仅查询本地状态，不请求飞书或平台，也不消耗模型 token。

旧飞书逐行发送工作流和字段保留但停用/隐藏，原批准不再代表本批授权。只有核验完成的顶部发送模式才能使用新入口。配置中断会持久锁定操作，重新核验配置后恢复；未完成发送只恢复核对，不自动续发。停止本次发送会中止批次后续选行，未选中的草稿保留；已提交的平台发送不能撤回。

飞书 CLI 未提供此路径下的条件更新接口，发送前使用多次读取核验；不要在系统正在处理同一行时同时编辑。两平台评论展开有数量及次数上限，全量分页完整性未验收；“部分评论”不能证明未看到的回复不存在。不包含全部作品自动发现、离线后台常驻或第三方账号代发。

### 左侧 AI 对话执行任务

左侧对话可请求“查看评论回复任务状态”“同步评论并回填平台回复”“发送本次填写好的评论回复”“停止当前发送”或“核对未确认的发送结果”。Agent 通过现有 `workbench` 工具的 `reply-sync` 执行，复用同一回复表和发送日志。`collect`/`sync` 只采集归档和回填；只有显式 `send-pending` 可以发布。旧自动模式不再对工具公开。

点击聊天停止会中止当前工具调用；手动批次用 `cancel` 停止，是否可取消由 `canCancelSend` 表示。已派发的发送不能撤销，中止后仍需只读核对，不能重发。取消信号只作用于该调用持有的任务。

每次回复任务的工具结果附带 `execution.startedAt`、`finishedAt` 和 `durationMs`，其中耗时使用单调时钟。它覆盖该次服务调用，不包含模型思考和聊天排队；完整实测需另记左侧提交至任务结果完成的时间。验证码等待应单独说明，不能用一次测试承诺固定耗时。
